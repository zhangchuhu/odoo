# Operations workbench

Implement a native OWL client action with navy navigation, white scope header and compact Chinese cards. A session ORM facade checks Editor for mutations and Worker for reads, uses company record rules, and never serializes lease secrets. Existing immutable snapshots hold manually supplied shop/item/title/SKU/inventory facts (unknown stays null); UI makes no claim to live platform statistics.

1. RED: TransactionCase tests for creation, scoped reads, Worker mutation denial, foreign/stale candidate rejection, exact proposal confirmation and recovery.
2. GREEN: narrow ORM methods for overview, case detail, manual snapshots, artifact-aware tasks, proposals and task controls. Bind proposals to case revision, snapshot, task result digest and candidate index/order.
3. Native OWL list/detail/forms, supported-task inputs and useful result cards with expandable audit evidence. Confirmation is separate from proposal preview; execution, ads and effects explicitly unavailable.
4. Run disposable Odoo HTTP suite and existing pure/worker/MCP suites. Static XML/JS checks and browser QA where environment supports it. Preserve outputs and live database/configuration.
