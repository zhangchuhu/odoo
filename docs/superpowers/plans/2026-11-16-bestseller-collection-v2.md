# 爆款采集 V2 Implementation Plan

**Goal:** 将飞书方案中的采集流程独立实现于现有 Odoo 及 Codex 宿主，保留历史数据。

**Architecture:** Odoo 保存不可变来源、平台和筛选阈值并编排任务；持有租约的 Codex 宿主提供真实视觉与 Chrome 采集证据，验证后可恢复地写入公司图库。无宿主时显示等待，不能伪造成功。历史导入保持可见。

**Tech Stack:** Odoo 19、OWL、Python、PostgreSQL、SQLite、现有 Chrome 采集器。

**Spec:** 飞书《爆款采集V2》，文档修订版 162；嵌入任务表待读取权限。

## Global Constraints

- 不依赖飞书作为运行时数据源，不使用 Ark；不主动处理真实业务图片。
- SHEIN 必须满足评价数和评分；Mercado Libre 必须满足销量；其他未显示的指标保留未知。
- 原图、平台、阈值、结果数量与当前快照绑定；禁止过期租约写入。
- 三组搜索词、每组 30–50 可见卡片，去重后固定顺序逐页核验，拒绝原因可审计。
- 等待、空结果和成功区分；重复执行和中断恢复不得产生重复或未核验结果。

## Tasks

- [ ] TDD：Odoo 验证任务字段、持久化快照并自动推进事实、关键词和研究阶段。
- [ ] TDD：采集证据绑定快照阈值和来源；校验平台规则、去重顺序及拒绝原因。
- [ ] TDD：合格结果幂等写入公司图库并支持断点恢复、回读核验。
- [ ] TDD：独立采集表单、状态、历史记录与有效依赖选择界面。
- [ ] 独立审查并运行 Worker、Odoo、浏览器与前端回归；明确真实宿主能力限制。
