# 简化首页采集与验证码恢复实施方案

> 执行时使用 `executing-plans`，先在开发分支实现和验证；本文件是方案，不表示功能已完成。

**目标：** 优先使用平台联想词，只采每个搜索词的首页；在任务或浏览器中断后依靠持久化进度恢复；验证码可由 Codex 有界尝试，未解决时等待用户，验证后恢复。

**架构：** 墨西哥站新任务采用不可变策略 `card-home-v4`；商品准备、搜索计划、首页采集、详情核验、视觉判断和图库入库均由任务作用域的 Worker 协调。联想词读取不要求先锁定正式搜索计划或绑定采集专属标签；正式采集与数据写入仍按任务、公司、快照和租约隔离。v2/v3 历史任务保持原协议。

**依赖：** Odoo、Python、SQLite、Chrome MV3、现有 Codex 电脑操作与视觉宿主、unittest、node:test、Odoo 浏览器测试。

**当前工作区进度：** 已有首页排程、卡片筛选、联想词读取/来源与准备信息、受限验证码尝试计数、恢复页面身份判断的基础模块及局部测试。尚未将 v4 策略贯通正式采集 Worker、浏览器操作、任务状态和结果回传；验证码自动操作及验证后恢复尚未接通。不得将这些基础模块视为功能完成或部署验收。

## 全局规则

- 墨西哥女装裙装套装核心词为 `conjunto mujer falda`；其他品类依据源图和商品类别决定，不把长裙、颜色或尺码当作套装类别的必备条件。
- 联想词是平台页面可见的建议，按原始内容和顺序记录，不将其标为已验证的搜索热度。读取的浏览器只要求墨西哥站、输入框内容及联想列表可核验，不借用正式采集页绑定回执。
- 初始词 3 组：核心词 1 组，相关的平台建议优先用于其余 2 组；不足时使用有源图依据的回退词。完成已选首页后，跨词去重的明确销量卡片不足 100 时继续扩词，每次 1–3 组、总数最多 9 组；无相关新词则结束。不得以固定时间预算提前结束搜索。
- 每词仅采首页，可滚动加载首页，不导航到第 2 页。每词取销量明确且严格 >100 的商品，按可证明销量降序、首次观察顺序及商品 ID 排序，最多 30 个；跨词合并去重。100 个扩词指标包括所有明确销量卡片；不等于强制选入 100 个。
- 商品详情销量明确且 >100 才进入视觉候选；大于等于用户创建任务时设置的 `min_sold` 为达标，低于该门槛但 >100 为补充，分开保存。最多 30 个详情通过者全部完成视觉判定后排序，不因先达到结果目标而提前结束；选入的两类结果都走图库回执。
- 采集批次写入需检查公司、任务、快照、当前租约、墨西哥站、当前搜索词和商品 ID；失败时拒绝当前批次，不复用过期租约。浏览器窗口和标签可重新创建，不能把历史标签 ID 当作恢复前提。
- 技术性自动重连最多 3 次，建议退避 2、5、10 秒；平台验证码自动交互最多 2 次，等待后台自动放行不计交互次数。不为采集设置固定总时间上限。
- 验证提示、结果、身份凭证均为平台实际观察；验证码图片、短信、邮箱码、cookie、token 不写日志或自动转发。截图用于限定访问的页面证据时应遵守现有权限与保留策略。

## 运行状态与数据

- 阶段：`suggestions` → `search_home` → `detail` → `visual` → `gallery` → `complete`；每个阶段只从服务端已提交的检查点推进。
- 等待原因至少区分 `captcha_required`、`login_required`、`page_unreadable`、`search_mismatch`、`browser_unavailable` 和 `platform_blocked`；不得以结果为空代替无法访问。
- 每个查询记录文本、来源 `category_anchor` / `platform_suggestion` / `image_fallback`、原始显示顺序、是否完成首页、分批结果及首页结束证据。可见联想词记录前缀、显示文字、原位置、时间、站点和证据摘要；不能把模型改写后的词伪装成原始建议。
- 候选记录保留商品 ID、搜索词来源、销量原文与可证明下限、首次观察顺序、详情与视觉结果；后台强制幂等去重。证据和检查点有公司和任务访问边界。
- 手动验证等待时停止任务续租，并保留检查点。后台观察验证结果只能使用明确授权的页面和任务范围；当页面明确可继续时，通过现有受控恢复接口申请新租约一次，再重新核验站点、查询或商品 ID。观察进程异常、页面关闭或用户取消时不无限创建请求。

## 任务 1：版本与计划生成

**文件：** `addons/meli_optimization/models/library.py`、`models/collection_start.py`；`optimization_worker/collector_cli.py`、`visual_profile.py`、`research_bridge_protocol.py`、`research_return_bridge.py`、`interactive_dispatcher.py`；`home_suggestions.py` 和相关测试。

1. 新建 `card-home-v4` 配置与协议：初始 3 词、最多扩展 6 词、每词 1 页、100 个明确销量目标、每词最多 30、视觉最多 30。验证快照、计划及用户阈值一致；v3 参数不可被迁移覆盖。
2. 读取建议前，核验源图属于当前任务公司和快照、哈希一致；使用可访问墨西哥站的浏览器读取实际搜索框和建议列表。读取工具不能依赖正式计划或旧的专属任务标签绑定。
3. 增加结构化观察结果：`observed`、`unavailable`、`blocked`、`unverified`；不可将未加载或访问被拒当作有效空结果。与源图信息一起评分、去重并生成最终初始 3 词，然后一次性锁定正式计划；后续扩词仅在授权范围内有序追加。
4. 检查当前工作树中未完成的 `home_suggestion_bootstrap.py` / `prepare_suggestions`：它们可以保留任务与源图隔离，但不得要求完成原有正式浏览器绑定才能读取建议，也不能将未验证的建议冒充平台观察；移除或修改与本方案冲突的部分。
5. 测试：两条前缀、重复/大小写/重音、无关裤装、风格不确定、平台不可读、来源标注、源图/公司不匹配、v2/v3 原计划不变、同一次请求幂等。

## 任务 2：首页采集与恢复

**文件：** `chrome_extension/content.js`、`home_suggestions.js`、`card_v3_collector.js` 或独立 v4 采集器；`home_collection_policy.py`、`card_sales_v3_checkpoints.py`、`collector_progress.py`、`tab_receipt_store.py`、`tab_receipt_supervisor.py`、`prepared_search_recovery.py`。

1. 为 v4 增加首页状态机：`pending`、`collecting`、`complete`；不调用后续页 URL 或保存第 2 页回执。首页为空必须有明确无结果证据，加载中或验证码不算结束。
2. 自动打开采集标签并搜索当前词，确认站点和搜索词后批量读取；滚动遇到虚拟列表时不能要求旧卡片仍在 DOM 中。每批幂等写入，稳定加载结束后封存该词。
3. 换租约或标签丢失时，授权复制同任务/公司/快照的已确认业务检查点，但不复制旧浏览器身份；重新打开未完成首页，以商品 ID 去重。完成的首页不重跑，已完成详情、视觉和图库回执继续复用。
4. 将当前合并的 `checkpoint_binding_invalid` 拆为可定位的受限错误码：任务、租约、站点、搜索词、标签、扩展、保存回执；只记录白名单元数据和步骤，不打印敏感内容。
5. 测试：首次执行、中途关闭标签、Worker 重启、租约更换、首页动态加载/列表虚拟化、重复商品、首页 403、零结果、三次重连失败、跨任务数据不能恢复、v3 仍最多三页。

## 任务 3：验证码处理

**文件：** `chrome_extension/content.js`、`interactive_dispatcher.py`、`host_session.py`、`research_return_bridge.py`、`research_service.py`；Odoo `models/optimization.py`、`models/library.py` 和工作台 JS/XML。

1. 发现验证码后先持久化当前检查点；记录阶段、实际观察到的验证类型、是否需要交互、尝试次数和状态。不能将已过期租约继续用于写入。
2. 先等待短暂的无交互自动放行；页面仍要求点击或图片选择时，由现有 Codex 浏览器/视觉能力在当前验证页面尝试，最多 2 次。以平台实际返回的页面状态为成功依据，不能以点击完成代替验证通过。
3. 需要短信/邮箱码、用户操作，或两次尝试失败时，任务进入等待并停止续租；工作台显示“打开验证页面”、具体状态和已保存进度。不得自动索取、记录或转发验证码。
4. 用户处理后，按已授权范围观察页面是否离开验证并恢复可读取状态；再重新核对站点及搜索词/商品身份，申请新租约并从检查点继续。若无法确认页面已经通过则保持等待，并提供手动恢复入口。
5. 测试：无交互放行、一次通过、两次失败、验证码持续、需要短信、用户完成后自动恢复、页面被关闭、误检、验证码出现于搜索和详情阶段、重复回调与租约过期。真实验证码功能仅在实际出现且经许可的页面验证，模拟测试单独标注。

## 任务 4：筛选、页面与回传

**文件：** `home_suggestions.py`、`home_collection_policy.py`、`card_sales_v3.py`、`card_sales_v3_pipeline.py`、`visual_v3_finalize.py`、`research_result_candidates.py`、Odoo `domain/contracts.py`、`models/library.py`、工作台 JS/XML。

1. 仅在所有已选词首页封存后冻结队列；每词按明确销量 >100 排序取 30，跨词按商品 ID 去重，保留搜索来源。销量冲突标记为不可确认，不拼接其他商品或店铺销量。
2. 沿用任务阈值分层和最多 30 个视觉判断；保留原有相似度与图库入库边界。显示搜索词来源、已完成查询、每词卡片、销量明确、详情/视觉进度、达标/补充分层及结束原因。
3. 测试 +100 排除、+101 接受、阈值 500 与其他阈值、重复/冲突销量、候选不足、不提前结束视觉判断、补充候选图库入库和历史页面兼容。

## 任务 5：验证、部署与合并

1. 开发分支运行 Worker 全量 unittest、全部 Node 扩展测试、Odoo `run_optimization_odoo.py --http --browser`、`git diff --check` 和 XML 校验；增加覆盖全部策略分支的端到端模拟测试，特别验证任务终态不再续租、等待验证码不被反复领取。
2. 测试通过后提交并推送开发分支。本机部署目录从开发分支更新，保留较新的本机 Odoo 基础代码和既有工作；备份后升级模块和重启受影响的服务，扩展变更后重新加载。
3. 使用已授权商品 `MLM4122505286` 创建新的 v4 验证任务，确认实际建议或回退来源、每词仅访问首页、销量和视觉分层、详情和图库回传。以可恢复的受控操作测试一次标签关闭或 Worker 重启；记录任务 ID、计数、错误码、终态和队列后续任务是否可推进。
4. 若真实验证未出现验证码，只报告模拟覆盖，不声称真实验证码已验证。任何平台或宿主阻塞保留检查点和诊断。
5. 所有必要测试和真实端到端验证通过后，才将开发分支合并主分支；未通过时不合并。
