**Goal:** 实现使用 Odoo API Key、隔离店铺并管理 OAuth 的 Python Mercado Libre BFF。

**Architecture:** 新增 Odoo 19 模块 `meli_bff`，依赖 `meli_accounts`，使用 `/api/meli` 路由直接调用固定 Mercado Libre 上游。复用店铺存储及授权回调，抽取独立事务凭证服务。HTTP 边界、业务映射和凭证事务分别测试。

**Tech Stack:** Python、Odoo 19、PostgreSQL、requests、Werkzeug、Odoo TransactionCase/HttpCase、unittest。

**Spec:** `docs/superpowers/specs/2026-09-28-erp-bff-design.md`，用户已确认。

## Global Constraints

- 统一使用 `/api/meli` 前缀，不提供旧代理入口。
- 上游固定为 `https://api.mercadolibre.com`，关闭自动重定向。
- Odoo API Key Bearer 鉴权；店铺归属检查必须先于提权读取凭证。
- 最大请求体 200 MiB，默认超时 120 秒；图片文件最大 10 MB。
- 更新后的 token 独立事务持久化；不得提交调用者无关业务变更。
- 写操作不自动重试，响应和日志不得暴露凭证。
- 描述更新转换 JSON；其余透传请求保持原始字节。
- 第一版创建接口支持传统 Global Selling，User Products 创建明确返回不支持。
- 测试使用新建隔离数据库，不对真实店铺发起商品写操作。

## Review Focus

1. multipart 被 Odoo 提前解析：上游收到的 boundary 和字节必须与原请求一致（任务 3）。
2. 身份字段混入 query/form：不能覆盖路径中的店铺 ID 或服务端租户（任务 3）。
3. 两个工作进程刷新同一凭证：只能成功轮换一次，其他请求读取新凭证（任务 2）。
4. 描述更新发送到错误接口或其他物流站点：使用绑定站点及 `/global/items/{id}`（任务 1）。
5. 响应压缩、重复头、Connection 指定头及传输中断：字节与头一致且释放连接（任务 3）。

- `filtered_response_headers(headers)`：返回保留重复头的列表，移除 hop-by-hop 与 cookies。

## Task 2: Durable shared OAuth credentials

**Interfaces:** 店铺 `_token()` 仍返回 `str`；内部 `_credential_token()` 在独立真实数据库 cursor 内获取最新有效凭证。

- [ ] **1. 添加事务失败测试**：新建隔离库中提交测试店铺；过期 token、模拟平台轮换成功后，再故意回滚调用者事务。独立 cursor 读取应仍是新 token，而调用者测试业务修改应未提交。

```python
token = store._token()
self.assertEqual(token, 'rotated-access')
caller_cr.rollback()
with registry.cursor() as verify_cr:
    verify_cr.execute('SELECT access_token FROM meli_independent_store WHERE id=%s', [store_id])
    self.assertEqual(verify_cr.fetchone()[0], 'rotated-access')
```

- [ ] **3. 实现独立事务凭证服务**：使用 registry 新 cursor、行锁和读后复核；保存 access/refresh/expiry。业务 cursor 仅先做 ACL 检查，独立 cursor 重新检查有效用户、公司与店铺，避免利用并发撤权。
- [ ] **4. 防止刷新锁问题**：使用有界锁等待，数据库序列化冲突最多重开事务重读；只有尚未发出平台刷新请求才可自动重试。平台请求已发生后，不重放 refresh token。未提交的新店铺或调用者已锁定同一店铺时返回清晰错误，不能永久等待。
