# MCP Streamable HTTP Implementation Plan

> 已被全量Global Selling扩展取代：本计划九项操作范围已停止推进，草稿未部署。后续依据2026-11-07-global-selling-registry-design.md制定新计划。


> **For agentic workers:** Use executing-plans for inline execution and a final independent review.

**Goal:** 用 Streamable HTTP 替换 stdio，并对接已部署 Odoo /api/meli。
**Architecture:** 无状态 /mcp POST，每次请求独立 server/transport；服务端 MCP bearer → Odoo API key 映射。四个元工具仅列出实际 BFF 支持的九项操作。
**Tech Stack:** Node.js、现有 MCP SDK 1.27.x、Zod、Axios。
**Spec:** 已确认六层链路和当前用户“开始改造mcp”；内部适配层设计作为下游依据。

## Global Constraints
移除 stdio；不实现长任务；仅本机部署，不修改远端，不执行真实平台写测试。
保留公司和店铺校验在 Odoo；不将模型参数或任意header当作身份；MCP bearer与Odoo API Key分离。

## Review Focus
跨用户凭据串用、非法Host/Origin、BFF重定向、未知工具与路径注入、图片超限及非标准base64。

## Tasks
- [ ] 备份原项目；在临时副本编写失败的 HTTP、BFF映射和身份隔离测试。
- [ ] HTTP入口：/mcp、认证、Host/Origin限制、请求体上限、无状态transport、优雅关闭；默认127.0.0.1:8071。
- [ ] 九项操作：shops、shop、search_items、get_item、create_item、update_item、get_item_description、update_description、upload_picture；路径仅/api/meli，JSON无旧item/body额外包装；严格参数校验。
- [ ] 保留四元工具接口，移除无下游支持的Amazon等目录与stdio脚本；文档注明破坏性变化。
- [ ] 测试：SDK Client真实HTTP initialize/list/call、401/403/405/413、两身份并发、校验失败无下游调用、JSON/multipart正确、无重定向和错误凭据泄漏。
- [ ] 同步原项目；独立审阅；创建本机私有配置和API Key，launchd运行；实际只读list shops联调及重启验证。

## Decisions
初始本机实例映射一个运营身份（现有admin）；配置支持多个MCP访问token分别映射不同Odoo用户API Key，身份由Key决定。配置不进入源码或模型工具参数。
旧项目超过100项操作并非当前Odoo能力，停止广告不受支持接口；不伪装返回或扩展Odoo范围。
