# 三页卡片销量筛选实施计划

**目标：** 新建 Mercado Libre 采集任务按每个搜索词最多前三页、卡片销量明确且严格大于 100 排序取前 30 件，并将销量达标结果和低销量补充候选分开展示。

**架构：** 引入 `card-sales-v3` 策略和独立版本化检查点；Chrome 采集真实页面中的卡片、销量和分页证据，后端基于持久观察完成去重、前 30 签封及详情队列排序。详情销量、视觉证据、图库入库继续经过现有租约和回执边界。历史任务仍由原策略处理。

**约束：** 每词最多 3 页；先 3 组、后扩展最多 6 组；销量明确目标为跨词去重 100 件，包含低于 100 的明确销量；任务门槛由创建时指定；卡片和详情均须能证明销量严格大于 100；补充候选不算销量达标；不使用固定时间或详情数量预算；#290 保持原策略。

## 搜索和结果语义

- [ ] 冻结新任务 `strategy=card-sales-v3`、`initial_query_count=3`、`max_expansion_queries=6`、`max_pages_per_query=3`、`sales_known_target=100`、`top_per_query=30`，把已有 `min_sold` 和 `result_limit` 固定到任务快照。旧任务策略及原始请求不可变。
- [ ] 完成初始三词的第一页，再按页轮询至第三页或明确无下一页；已开始的当前词前三页或实际可用页须全部确认，才可计算此词前 30。搜索结束条件在完整词集合边界判断，不允许中页或中词截断导致前 30 不准确。
- [ ] 初始三词完成后统计跨词去重的销量明确商品；不足 100 时每轮扩展 1–3 个不同且不含颜色、尺码的相关词，累计最多 9 词。完成已签封词后，达到 100 或无可用搜索词/所有词处理完则冻结发现集合；无固定时间或详情数停止条件。
- [ ] 100 是卡片销量可明确解析的去重商品数，并非销量达标数，也非每词前 30 合并数。前三页或总词数用完时可能不足 100；页完全为空/无下一页须有可验证的页面证据，阻断或未加载不能当作完成。
- [ ] 每词跨页按平台和商品 ID 去重，只保留可证明销量下限 >100 的卡片；按可信销量下限降序、首次发现顺序、商品 ID 排序取最多 30。`+100` 不能证明大于 100；`+150` 可证明。不得以任务的 500 门槛优先排序。
- [ ] 合并各词前 30 后再次按平台和商品 ID 去重，保留来源。冻结详情队列后按可信销量下限降序、首次发现顺序、商品 ID 排序；不重排已确认的详情。详情销量可证明 >100 且 >=任务门槛为 `threshold_met`，可证明 >100 但低于门槛为 `supplemental`，无可靠详情销量或不大于 100 的排除。两类分别计数和展示；仅销量达标且视觉合格并完成图库的计入达标目标，补充候选独立保存。
- [ ] 任务目标和最终状态明确：达到 `result_limit` 个达标视觉候选后可停止详情核验并入库其图库；否则处理冻结队列直至结束。补充候选已经发现则与达标结果分开展示，按结果契约完成其必要图库；结果不足时按结束原因报告，绝不声称补充候选达到任务门槛。

## 任务 3：分页检查点、去重和前 30

**文件：** 新增 `optimization_worker/card_sales_checkpoints.py`、`card_sales_policy.py`、`tests/test_card_sales_checkpoints.py`、`tests/test_card_sales_policy.py`；修改 `tab_receipt_store.py`、`tab_receipt_broker.py`、`native_collector_host.py`、`prepared_search_recovery.py`。

- [ ] 定义任务/计划/租约/词/页/批次作用域：页面身份、页序、观察时间、下一页证明、批次索引、商品身份、销量原文和解析、页面状态；业务观察与浏览器新租约回执分别保存。保证批次不可覆盖、严格有序和幂等。
- [ ] 完成页面时原子持久化结束证明；恢复时校验公司、快照、计划哈希、租约授权、页面顺序和浏览器绑定，重新核验新会话。包括已完成页面、当前页部分批次和详情队列；禁止旧浏览器回执跨租约复用。
- [ ] 前 30 仅在该词所有计划页面完成后计算并签封。根据可信销量下限排序并以首次发现顺序打破平局；跨词合并时保留每个词自己的入选依据。
- [ ] 对同一商品不一致观察保留原文与时间；无显示与明确显示不冲突；只在可证明销量区间互相矛盾时标冲突并排除。对 `+100` 与 `+150` 这类可重叠的下限不要误判为冲突；排序采用最新可信观察并固定到签封结果。
- [ ] 新增原子化 `sales_known_target=100` 去重计数；若新词集签封后已达到目标，仍完成该已启动词的前三页，再结束发现。候选集、目标计数和进度必须可由持久观察重建。
- [ ] 测试同批重放、篡改、跨页/跨词重复、冲突区间、未完成词不能选前 30、末页超越目标、跨租约恢复和并发租约失效。

## 任务 4：调度、详情筛选及结果保存

**文件：** `collector_progress.py`、`collector_import.py`、`visual_candidate.py`、`visual_v2_finalize.py` 或新增 v3 结果模块、`candidate_image_upload.py`、`archived_recovery.py` 及对应测试。

- [ ] 建立状态机 `initial_homepages → initial_remaining_pages → expansion_homepages → expansion_remaining_pages → freeze_candidates → detail_review → gallery → complete`，每步可重复执行，失败进入可恢复等待；所有词达到三页视为该词范围用完，不依赖平台总页数。
- [ ] 后端从完整的每词前三页独立重算前 30 和合并顺序；宿主不能提交未经签封或未入选的商品。若前 30 内低于任务门槛，保留补充资格但不能记作达标。
- [ ] 详情校验商品身份、销量文本和解析；两类结果必须能证明 `>100`，再以任务门槛区分 `threshold_met`/`supplemental`；无销量直接排除。建立回执，保留卡片及详情各自原文、下限、时间和来源。
- [ ] 两类结果分别进行既有一级、二级、风格和场合判断。保留 `highly_similar`、`competitor`、待核对与排除原因，保证来源图、候选原图及回执一致。只有视觉通过且详情销量达标的商品计入 `result_limit`。
- [ ] 保持现有受控图库清单、原图下载与入库；结果提交时再次重建候选身份、筛选分层和图库回执。结果中 `qualified_candidates`、`supplemental_candidates` 单独保存，确保运营页面及已有 result schema 消费者兼容；不得直接修改历史结果契约而破坏旧任务。
- [ ] 按页/批次分块持久证据与哈希清单，不将无限卡片数据拼进原有 5 MB 单一 JSON；确认上传、断线对账、恢复重复提交、缺失块和哈希冲突。
- [ ] 覆盖 `min_sold` 小于、等于及大于 100 的边界：通过卡片严格 >100 是共同门槛，达标判断还须 >= 用户门槛。明确高销量达标、低销量补充、图片不一致、结果不够的完整结束路径。
